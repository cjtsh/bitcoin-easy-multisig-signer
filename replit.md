# Agent entry point

Read [`CURRENT-STATUS.md`](CURRENT-STATUS.md), `AGENTS.md` and `PHASE-HANDOFF.md` first, then [`RELEASE-HISTORY.md`](RELEASE-HISTORY.md), then source and tests. **The published set is what the GitHub Releases page and `RELEASE-HISTORY.md` carry** — do not restate a "current published release is X" here; that sentence is the CT-46/CT-71 defect class and it went stale at 0.6.3 while the tree moved on. Version 0.7.2 is the current source revision: it answers the ⚠️ CONDITIONAL Color Team audit of the `v0.7.1` tree. The grade-binding finding, CT-22, was that a wallet's unconfirmed-payment pause gated preparation but not the broadcast, so a second fully reviewed payment could be submitted while the first was unconfirmed whenever the explorer said nothing about the first spend; `_broadcast` now refuses at the submit and re-asserts the refusal under the lock the submit takes. A transaction that names the same Bitcoin output twice is refused before any explorer is asked (CT-24), and the transport tuples now include `http.client.HTTPException` so a peer that is not speaking HTTP is the documented refusal on the settings, explorer and broadcast paths instead of a fixed 500 (CT-25). Rows `CM-38`…`CM-42` pin all of it and `releases/PATCH-0.7.2.md` is the ledger. This is the first revision since 0.5.1 that changes app behaviour rather than only the build: `gui.py`, `wallet_service.py` and `network_settings.py` change, and no transaction construction, signing, fee or network rule changes with them. Version 0.7.1 was the Color Team cycle-7 build-process remediation of the `v0.7.0` tree, with a discriminating pin on the loopback server's retired-connection guard, a control inventory that parses the GitHub workflow files so the retired-publisher pagination guard and the notarisation and checksum-signing credential guards are tracked rows with executable pins, a busy-slot docstring that says what the slot actually requires, terms of use that incorporate the Bitseeker LLC standard legal framework, and no wallet, signing or broadcast policy change. Version 0.7.0 was the cycle-6 build-process remediation of the `v0.6.9` tree, with discriminating pins on the value and script limbs of the build-time prevout match, a connection ceiling that retires an idle socket instead of refusing the operator's window, a control inventory that now tracks the protections 0.6.9 added untracked, a retired-publisher guard that refuses on a registration list larger than the one page it reads, a bounded Windows startup dialog, and no wallet, signing or broadcast policy change. Version 0.6.9 was the cycle-5 remediation, with content-bound `CONTROLS.md` citations, first-line money-path guards pinned by their own named tests, and an address bar that no longer carries the local access token. Version 0.6.8 was the cycle-4 remediation, which introduced the checked audit ledger and the parsed `CONTROLS.md` control inventory. Version 0.6.2 retired the network of a finished review together with the review; version 0.6.1 moved practice networks behind developer mode; and 0.5.1 first published mainnet broadcast behind explicit final-screen confirmation and a backend opt-in. `PROJECT-HISTORY.md`, the earlier phase detail in `ROADMAP.md`, and `releases/SECURITY-REVIEW-0.2.0.md` are archives. The app's user is a nontechnical spouse or estate professional; keep descriptor complexity in automatic checks, not on the main screen.

One engine serves Testnet4, Mutinynet and mainnet. The app reads an existing BSMS wallet, scans via Esplora, builds a PSBT, asks HWI hardware signers to sign, verifies the returned signatures and final transaction, and can broadcast to the selected network only after the required confirmation. Mainnet requires both the final-screen confirmation and backend opt-in; nothing broadcasts automatically. One live mainnet transaction has been prepared, signed on two hardware devices, broadcast and confirmed by this project. It never creates wallets or requests seeds/PINs. Receive-only exports are Send All only because they do not establish change ownership.

0.2.0 was the hot-audit-fix milestone, but it broke hardware signing; do not use it for signing. Check `CURRENT-STATUS.md`, `PHASE-HANDOFF.md`, and `RELEASE-HISTORY.md` for current status and evidence. Use a patch bump for a correction to a published build. Do not claim physical-device acceptance from automated tests alone; it requires a recorded physical walkthrough. The Mac workflow is manual dispatch only, with hash-locked dependencies and a required libusb digest. Published Mac releases use Developer ID signing and notarization; unsigned test artifacts are explicitly labelled. Do not republish an existing version or put wallet material in source, diagnostics or CI.
